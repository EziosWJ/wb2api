# wb2api v1.9.44

修复渠道校验失败误伤账号、模型繁忙被记为额度耗尽，以及上游缓存命中字段为零时的统计遗漏。参考上游主线为 [`73a7560`](https://github.com/linguo2625469/workbuddy2api-panel/commit/73a7560efc7a88ebd9865db4c71ae7f6d85859f8)，截至 2026-10-22 没有新的主线提交；该仓库已于 10 月 21 日宣布停止维护。本版筛选适配错误分类、缓存统计和模型状态显示相关更新。

## 修复内容

- 渠道校验失败按 `channel_refused` 处理。识别 `11128`、`11-128` 和 `111-28` 的渠道拒绝文案，保留原始错误正文，支持 HTTP、SSE、嵌套错误信封与 message 内的原始 JSON。此类错误不累计账号故障、冷却或禁用；`11140 + request illegal` 保持原有三次禁用阈值，同码的安全策略拦截保持原有处理。业务码按结构精确识别，requestId 中的 `12153` 不再误触发会话失效。
- `14003` 模型繁忙默认冷却 10 秒，只影响该账号的该模型。上游明确给出恢复时间或 `Retry-After` 时记录原始截止时间，并遵守 `soft_rate_max`；重复的同一截止时间不延长当前窗口。只有全池候选均因繁忙不可选、且最早恢复时间在 10 秒以内时，同一请求等待后重试一次。等待可取消，仍繁忙则返回 `503 model_busy` 和 `Retry-After`。已输出内容的流不重放。
- `14003` 不作为额度耗尽，不触发付费 SG 或国内回退。混合额度、权限、并发、余额或每日 Token 限制也不误报为全池额度耗尽。`6004` 即使缺少恢复时间，也只冷却该模型，其他模型继续可用。
- 请求在 SG 或国内阶段等待期间，国际免费额度或 SG 恢复时，会重新检查较便宜的阶段。保留国际免费 4.1 → 国际 SG → 国内同名 4.1 的顺序；SG 和国内继续要求已知余额高于保留积分线，并遵守每账号、每模型每日 Token 上限。
- 缓存命中为零或缺失，但上游明确提供未命中量和输入量时，按两者差值补齐命中量。已有正的命中量优先，缺少未命中数据时不猜测。客户端响应、流式统计和非流式统计使用同一口径，保留跨帧观测；输入、输出、总 Token 和实际扣费保持原值。这项更新修正统计，不改变上游实际计费。
- 账号页分别显示模型繁忙、额度限流、权限不足和模型不可用。网关冷却时间被封顶时，提示同时显示下次重试时间与上游重置时间。

错误分类参考 [PR #233](https://github.com/linguo2625469/workbuddy2api-panel/pull/233)，缓存推导参考 [PR #199](https://github.com/linguo2625469/workbuddy2api-panel/pull/199)，时间显示参考 [PR #203](https://github.com/linguo2625469/workbuddy2api-panel/pull/203)。繁忙窗口和短等重试参考 [misakano7545 社区分支](https://github.com/misakano7545/workbuddy2api-panel)。所有适配均保留本仓库的 Fill First、无前缀路由、国内与国际分区以及凭证导入导出。

## 验证与升级

全量 `go test ./...`、`go vet ./...` 以及 pool、upstream、server 的 `-race` 测试通过。回归覆盖渠道拒绝连续请求、繁忙截止时间、单次等待与取消、免费额度恢复、混合冷却、付费回退边界和缓存观测。面板 JavaScript 语法及状态显示验证通过。

容器镜像为 `ghcr.io/csszyft/wb2api:v1.9.44`，同时更新 `latest`，支持 Linux amd64 / arm64。Release 提供 Windows amd64、Linux amd64 / arm64、macOS amd64 / arm64 压缩包和 `SHA256SUMS`。

