# wb2api v1.9.37

修复账号 JSON 导入只接受 cockpit 数组、无法导入本程序 auth 文件的问题。账号池新增每账号、每模型的每日 Token 用量与上限。

## JSON 导入

在「添加账号 → 导入 JSON」选择一个或多个文件。支持：

- 本程序保存的 `auth` + `account` 嵌套凭证。
- 单账号对象、账号数组、accounts/data 等嵌套导出、以账号为键的字典、JSON 字符串包装。
- camelCase、snake_case、PascalCase 字段；UID 支持 uid/userId/accountId。
- 秒或毫秒过期时间、数字字符串和 RFC3339 日期，保留 realm、enterpriseId、device_token 等信息。

最低需要 UID、accessToken 和 refreshToken。程序会逐条验证，跳过残缺或冲突条目，同一文件重复 UID 保留首个有效条目。不会将不同账号的凭证拼在一起。导入失败原因直接显示在面板中。

缺失过期时间时标记为待刷新，不再假定令牌一年有效。单文件上限 32 MiB。只有状态、余额或用量的 JSON 不含登录凭证，无法用来恢复账号。

## 每账号、每模型每日上限

进入「账号池 → 对应账号 → 模型用量 / 限额」：

1. 查看当天各模型的输入、输出、合计 Token。
2. 输入模型名称与上限，例如 `100M`，点击「保存限额」。
3. `100M` = 100,000,000 Token；也支持 `500K`、`1.5M` 或整数。`0` 表示不限。

上限默认不设置，保存后立即生效。输入与输出合计，包含缓存命中的输入 Token。按北京时间每天 00:00 重置，与服务器时区无关。

某账号的某模型达到上限后，新请求跳过该账号；其他账号和模型照常。普通选号、粘性会话、冷却探测兜底和 SG 自动回退均执行限制，在取得并发名额时再次检查。所有候选均达本地上限时返回 `429 daily_token_limit`，附带下一次重置时间和 `Retry-After`。

免费 `global:deepseek-v4.1-flash` 的本地上限与上游模型限流共同决定免费池是否耗尽。启用现有 SG 回退开关时，全池免费额度不可用才回退 SG；SG 自己的每日上限和保留积分仍生效。

上限和计数保存到 state.json，重启后保留。首次升级会从现有 usage.json 恢复今天已记录的用量；中途设置、提高、取消上限都不会清空已有计数。模型带区域前缀和裸名归为该账号的同一个模型。

这是基于网关 API 请求实际用量回报的派发限制：进行中的回复会继续完成，并发请求或最后一次回复可能使日累计超过上限。未返回 usage 的断流/失败请求无法精确计量，面板会显示无用量回报次数。账号在其他客户端直接使用、定时任务和面板诊断调用不进入这份 API 计数；多个独立网关实例不共享实时预算锁。

## 上游与验证

已重新拉取参考上游，最新仍为 `8461419`，相较 v1.9.36 没有新增提交。保留此前同步内容和本分支的 Fill First、国服/国际服分栏、SG 回退及界面。

验证包括本程序凭证导出再导入、不同 JSON 包装、冲突字段和无凭证条目、Token 单位解析、北京时间跨日、重启持久化、并发计数、模型隔离、粘性/兜底防绕过、429 返回及免费/SG 配额联动。浏览器使用隔离示例账号验证 100M 保存、达限展示和多文件导入。

## 升级

保留配置、auths 和 data，更新后重启。镜像：`ghcr.io/csszyf/wb2api:v1.9.37`。升级本身不会给任何账号自动设置 100M 上限，需要在面板按模型保存。
