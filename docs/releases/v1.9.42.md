# wb2api v1.9.42

适配 `deepseek-v4.1-flash`（1017 版本）原生多模态能力、思考档位就近匹配与 `-1017` 别名路由，并吸收上游社区在会话头校验、队列满载与网关 401 上的关键修复。

## DeepSeek V4.1-Flash (1017) 适配

- **原生多模态与上下文上限透出**：腾讯 WorkBuddy 上游已将 `deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-sg` 就地更新为 1017 版本（`supportsImages: true`、`maxAllowedSize: 1000000`）。修复 `/v1/models` 中写死快照覆盖上游动态字段导致 `deepseek-v4.1-flash` 丢失 `supports_images: true` 的问题，并同步更新内置兜底快照。
- **兼容 `deepseek-v4.1-flash-1017` 模型名别名**：支持直接请求 `deepseek-v4.1-flash-1017`（含 `global:` / `cn:` 前缀），网关自动归一为上游识别的 `deepseek-v4.1-flash`，并完整复用国际免费 → SG → 国内同名 4.1 的三级回退链。
- **思考档位就近匹配（`low/high/max`）**：`deepseek-v4.1-flash` 声明档位为 `low/high/max`（默认 `high`，无 `medium`）。当 Codex / OpenCode / ZCode 等客户端默认发送 `reasoning_effort: "medium"` 时，改为按最近距离优先对齐到模型默认档 `high`，不再降级为 `low`。
- **`reasoning_text` 思考片段提升**：兼容客户端/转换器发送的 `type: "reasoning_text"` 内容块，统一提升为顶层 `reasoning_content`，避免 `400 code=11101 unsupported content type` 并满足 DeepSeek 多轮工具调用的思维链回传要求。

## 上游与社区修复同步

- **补齐 `X-Conversation-ID` 请求级兜底（PR #190）**：未携带会话 ID 的请求自动生成 32 位 hex 兜底，确保 `X-Conversation-*` 三件套齐全，解决国际版 `global:deepseek-v4.1-flash` 偶发 `400 code=11128 conversation id missing`。
- **`6021 queue.full.title` 渠道级满载保护（PR #185）**：将推理集群排队满载（`code: 6021`）识别为 `upstream_busy`，直接返回 `503` 而不轮转、不冷却账号，防止高峰期 2 秒内把整池健康号全部软冷却。
- **网关层 401 失效会话识别**：将无业务信封的 APISIX `401 Authorization Required` 页面纳入连续 3 次阈值禁用（标注 `401 invalid token (re-login required)`），避免被上游注销的失效号长期留在池中。
- **`stop` 字符串形态归一**：将字符串 `stop` 自动转为单元素字符串数组，避免触发上游 `400 code=11101` 解析失败。
